## 1. CLI Terminal Design Tokens

### 1.1 ANSI Color Mapping

Katana uses the `colored` crate for terminal output. All colors map to standard ANSI 256 palette for maximum terminal compatibility.

```rust
// katana/src/output/colors.rs

/// Severity-level colors for triage output
pub mod severity {
    pub const CRITICAL: &str = "\x1b[1;91m";  // Bold bright red
    pub const HIGH: &str     = "\x1b[91m";     // Bright red
    pub const MEDIUM: &str   = "\x1b[93m";     // Bright yellow
    pub const LOW: &str      = "\x1b[96m";     // Bright cyan
    pub const INFO: &str     = "\x1b[37m";     // White
    pub const RESET: &str    = "\x1b[0m";
}

/// Structural element colors
pub mod structure {
    pub const HEADER: &str     = "\x1b[1;97m"; // Bold bright white
    pub const SUBHEADER: &str  = "\x1b[1;36m"; // Bold cyan
    pub const LABEL: &str      = "\x1b[90m";   // Dark gray
    pub const VALUE: &str      = "\x1b[37m";   // White
    pub const PATH: &str       = "\x1b[33m";   // Yellow (file paths)
    pub const TIMESTAMP: &str  = "\x1b[34m";   // Blue (timestamps)
    pub const COUNT: &str      = "\x1b[1;32m"; // Bold green (numeric counts)
    pub const HASH: &str       = "\x1b[35m";   // Magenta (SHA-256, hashes)
    pub const SEPARATOR: &str  = "\x1b[90m";   // Dark gray (lines, borders)
    pub const RESET: &str      = "\x1b[0m";
}

/// Progress and pipeline stage indicators
pub mod progress {
    pub const ACTIVE: &str   = "\x1b[1;96m";  // Bold bright cyan
    pub const DONE: &str     = "\x1b[32m";     // Green
    pub const PENDING: &str  = "\x1b[90m";     // Dark gray
    pub const ERROR: &str    = "\x1b[1;91m";   // Bold bright red
    pub const SPINNER: &[char] = &['|', '/', '-', '\\'];
}
```

### 1.2 CLI Typography Rules

```
Terminal Assumptions:
- Minimum width: 80 columns
- Recommended width: 120 columns
- Font: User's terminal font (monospace by definition)
- Encoding: UTF-8 (box-drawing characters allowed)

Text Hierarchy:
- Section headers:  UPPERCASE, bold white, preceded by blank line
- Sub-headers:      Title Case, bold cyan
- Labels:           dark gray, right-aligned to column width, followed by colon
- Values:           white, left-aligned after label
- Emphasis:         bold (never italic -- terminals vary)
```

### 1.3 CLI Table Formatting

```
Column Rules:
- Minimum column width: 4 characters
- Column separator: " | " (space-pipe-space) in dark gray
- Header separator: "---+---" repeated (dark gray)
- Number columns: right-aligned
- Text columns: left-aligned
- Truncation: "..." suffix when content exceeds column width
- Maximum table width: terminal width minus 2

Example Output:
  TRIAGE RESULTS
  Question                          | Answer  | Confidence | Evidence
  ----------------------------------+---------+------------+---------
  Ransomware activity detected?     | YES     | HIGH       | 47 hits
  Data exfiltration indicators?     | NO      | MEDIUM     | 0 hits
  Lateral movement observed?        | YES     | HIGH       | 12 hits
```

### 1.4 CLI Progress Bar

```
Pipeline Stage Visualization:

  [Parse]---->[Correlate]---->[Triage]---->[Report]
    Done        Active         Pending      Pending

Single-line progress (for each stage):
  Parsing USN Journal... [=========>          ] 47% (1.2M / 2.6M records)

Streaming phase output:
  [1/4] Parsing USN Journal............ 2,614,831 records (1.2s)
  [2/4] Correlating MFT paths.......... 2,614,831 resolved (0.8s)
  [3/4] Running triage questions....... 12/12 complete (0.3s)
  [4/4] Generating report.............. report.html (0.1s)

  Total: 2.4s | Ghost recoveries: 1,847 | Triage hits: 127
```

### 1.5 CLI Error Formatting

```
Error Pattern (always to stderr):

  ERROR: <one-line description>

  Cause:  <technical detail>
  Fix:    <actionable next step>

  Exit code: <1 or 2>

Example:
  ERROR: Unsupported filesystem type: ext4

  Cause:  Katana supports NTFS only. Detected ext4 on partition 2.
  Fix:    Verify the image contains an NTFS volume.
         Supported: NTFS (MBR, GPT, E01, raw)

  Exit code: 2

Warning Pattern (always to stderr):
  WARN: <one-line description> -- <consequence or fallback>

Example:
  WARN: USN Journal not found -- falling back to unallocated carving only
```

### 1.6 CLI Color Disable Rules

```rust
// Color output MUST be disabled when:
// 1. stdout is not a TTY (piped to file or another command)
// 2. NO_COLOR environment variable is set (https://no-color.org)
// 3. --no-color flag is passed
// 4. TERM=dumb
//
// Detection order:
//   if args.no_color || env::var("NO_COLOR").is_ok() || !atty::is(Stream::Stdout) {
//       colored::control::set_override(false);
//   }
```

## 3. Framework Integration

### 3.1 Technology Stack Per Surface

| Surface | Renderer | CSS Approach | Template Engine |
|---------|----------|-------------|-----------------|
| CLI | Rust `colored` crate | N/A (ANSI escapes) | Hardcoded format strings |
| HTML Report | Rust binary generates static HTML | Vanilla CSS (embedded in `<style>`) | `askama` or string templates |
| Enterprise Web | Axum server | Vanilla CSS (external stylesheet) | `askama` templates |

### 3.2 HTML Report Integration

The HTML report is a single self-contained `.html` file generated by the Katana binary. All CSS is embedded inline within `<style>` tags. No external dependencies.

```rust
// katana/src/output/html.rs -- Structure
//
// The CSS custom properties from Section 2 are embedded verbatim
// into the <style> block of every generated report.
//
// Template structure:
//   <html>
//     <head>
//       <style>/* Section 2 tokens + Section 4 component CSS */</style>
//       <script>/* Tab switching + DataTables init */</script>
//     </head>
//     <body>
//       <nav><!-- Story | Explore tab switcher --></nav>
//       <main id="story"><!-- Narrative timeline --></main>
//       <main id="explore"><!-- Interactive data tables --></main>
//     </body>
//   </html>
```

### 3.3 Enterprise Web Integration (Axum + Askama)

```rust
// enterprise/src/web/templates.rs -- Structure
//
// Askama templates reference the CSS custom properties.
// Static CSS file served from /static/katana.css
//
// Route structure:
//   GET  /                    -> Dashboard
//   GET  /cases/:id           -> Case detail
//   GET  /cases/:id/timeline  -> Timeline view
//   GET  /cases/:id/evidence  -> Evidence explorer
//   WS   /ws/cases/:id        -> Real-time updates
//   GET  /static/katana.css   -> Design system CSS
```

### 3.4 Token Mapping Across Surfaces

| Semantic Purpose | CLI (ANSI) | HTML/Web (CSS) |
|-----------------|------------|----------------|
| Critical finding | `\x1b[1;91m` (bold bright red) | `var(--color-critical)` #ff4757 |
| High severity | `\x1b[91m` (bright red) | `var(--color-high)` #ff6b6b |
| Warning/medium | `\x1b[93m` (bright yellow) | `var(--color-warning)` #d29922 |
| Success/clean | `\x1b[32m` (green) | `var(--color-success)` #3fb950 |
| Informational | `\x1b[37m` (white) | `var(--color-info)` #58a6ff |
| Ghost recovery | `\x1b[35m` (magenta) | `var(--color-ghost)` #bc8cff |
| File path | `\x1b[33m` (yellow) | `var(--color-warning)` with `font-mono` |
| Timestamp | `\x1b[34m` (blue) | `var(--color-accent)` with `font-mono` |
| Muted/label | `\x1b[90m` (dark gray) | `var(--color-text-muted)` |
| Hash/checksum | `\x1b[35m` (magenta) | `var(--color-ghost)` with `font-mono` |

## 6. Responsive Breakpoints (Enterprise Web Only)

The CLI and HTML report are not responsive -- CLI fills the terminal width, and the HTML report targets desktop browser viewing during analysis sessions. The enterprise web UI supports tablet and desktop viewports.

### 6.1 Standard Breakpoints

| Name | Width | Use Case |
|------|-------|----------|
| `md` | 768px | Tablet -- case list or detail, single column |
| `lg` | 1024px | Laptop -- sidebar visible + content area |
| `xl` | 1280px | Desktop -- sidebar + content + evidence panel |

## 9. Accessibility Integration

This document provides **visual tokens and CSS implementation**. For comprehensive accessibility guidance, see ACCESSIBILITY.md when generated.

### 9.1 Coverage Matrix

| Concern | CLI | HTML Report | Enterprise Web |
|---------|-----|-------------|----------------|
| **Color contrast** | ANSI colors on dark/light terminal backgrounds | CSS token definitions (Section 2) | CSS token definitions (Section 2) |
| **Non-color indicators** | Severity text labels `[CRITICAL]` always present | Severity badges include text, not just color | Status dots paired with text labels |
| **Focus states** | N/A (no interactive elements) | Tab switcher focus ring | All interactive elements (Section 5.3) |
| **Reduced motion** | N/A | `prefers-reduced-motion` media query | `prefers-reduced-motion` media query |
| **Screen readers** | N/A (terminal handles this) | Semantic HTML (`<nav>`, `<main>`, `<table>`) | Semantic HTML, ARIA labels on dynamic content |
| **Keyboard navigation** | N/A | Tab between Story/Explore tabs | Full keyboard nav, skip links |
| **Color-blind safe** | Severity always has text label alongside color | Severity always has text label alongside color | Status always has text label alongside color |

### 9.2 Required Accessibility Tokens

```css
/* Focus ring -- 5.2:1 contrast against --color-background (#0d1117) */
--ring: #58a6ff;
--ring-offset: 2px;

/* Error states -- never rely on color alone.
   Always pair with icon (AlertTriangle) + descriptive text. */
--color-error: #f85149;
--color-error-subtle: rgba(248, 81, 73, 0.15);
```

### 9.3 Cross-Reference Checklist
