## 0. CLI Accessibility

CLI is the primary interface for community users and the foundation for all tiers. Since CLI output is inherently keyboard-operated, the accessibility focus is on visual output adaptability and screen reader compatibility.

### 0.1 NO_COLOR Compliance

Security Ronin Katana respects the [NO_COLOR standard](https://no-color.org/) and related environment signals. The `colored` crate in Rust handles most of this, but the implementation must enforce these rules:

```rust
// src/output/color.rs

/// Color suppression priority (checked in order):
/// 1. --no-color CLI flag (explicit user request)
/// 2. NO_COLOR environment variable (any value, including empty string)
/// 3. TERM=dumb (terminal does not support escape sequences)
/// 4. Non-TTY stdout (piping to file, grep, or another tool)
///
/// When color is suppressed:
/// - Strip ALL ANSI escape sequences from output
/// - Severity indicators use text prefixes: [CRITICAL], [HIGH], [MEDIUM], [LOW], [INFO]
/// - Ghost recovery entries use prefix: [GHOST]
/// - Progress bars use ASCII: [=====>    ] 60%
/// - Structure uses indentation and dashes, not color

fn should_use_color(args: &CliArgs) -> bool {
    if args.no_color {
        return false;
    }
    if std::env::var("NO_COLOR").is_ok() {
        return false;
    }
    if std::env::var("TERM").map(|t| t == "dumb").unwrap_or(false) {
        return false;
    }
    if !atty::is(atty::Stream::Stdout) {
        return false;
    }
    true
}
```

### 0.2 ANSI Color Fallback Strategy

Terminals vary in color depth support. Katana uses a tiered fallback:

| Terminal Capability | Detection | Color Strategy |
|--------------------|-----------|--------------------|
| 24-bit (truecolor) | `COLORTERM=truecolor` | Full design token hex colors |
| 256-color | `TERM` contains `256color` | Closest 256-color approximation |
| 16-color (basic) | Default TTY | ANSI 16-color severity mapping |
| No color | `NO_COLOR`, `TERM=dumb`, non-TTY | Text-only severity prefixes |

**16-color severity mapping (from UI_DESIGN_SYSTEM):**

| Severity | ANSI Code | Visual | Text Fallback |
|----------|-----------|--------|---------------|
| Critical | `\x1b[1;91m` (bold bright red) | Bright red, bold | `[CRITICAL]` |
| High | `\x1b[91m` (bright red) | Bright red | `[HIGH]` |
| Medium | `\x1b[93m` (bright yellow) | Bright yellow | `[MEDIUM]` |
| Low | `\x1b[96m` (bright cyan) | Bright cyan | `[LOW]` |
| Info | `\x1b[37m` (white) | White | `[INFO]` |
| Ghost | `\x1b[35m` (magenta) | Magenta | `[GHOST]` |

### 0.3 Screen Reader Compatible CLI Output

When output is consumed by screen readers (common when analysts use terminal emulators with assistive technology), the structure must be parseable as plain text:

```
=== TRIAGE RESULTS: case-2026-0310 ===

Evidence: laptop.E01
Processing time: 34.2 seconds
Records parsed: 1,247,832
Ghost records recovered: 14,207

--- Question 1: Was endpoint protection disabled? ---
Answer: YES (confidence: HIGH)
Severity: CRITICAL
Evidence:
  [1] 2026-03-08T14:23:17Z DELETE Windows Defender\MpCmdRun.exe
  [2] 2026-03-08T14:23:19Z DELETE Windows Defender\MsMpEng.exe
  [3] 2026-03-08T14:23:22Z RENAME Windows Defender\Platform\ -> .bak

--- Question 2: Was there evidence of lateral movement? ---
Answer: NO
Severity: INFO
Evidence: No matching USN journal entries found.
```

**Key principles for screen reader output:**
- Use consistent section delimiters (`===` for headers, `---` for questions)
- Prefix every severity with text label, not just color
- Number evidence entries for reference
- Use standard date/time formats (ISO 8601)
- Avoid Unicode box-drawing characters in default mode (use `--unicode` flag to opt in)
- Always include counts in plain text (not embedded in progress bars)

### 0.4 Pipe-Safe Output

When stdout is not a TTY (detected via `atty::is()`), Katana automatically:

1. **Strips ANSI escape sequences** -- no color codes in piped output
2. **Removes progress bars** -- no carriage returns or cursor manipulation
3. **Uses machine-parseable delimiters** -- tab-separated or JSON lines
4. **Preserves semantic structure** -- headers, evidence blocks, severity labels remain as text

```bash
# Human-readable (TTY)
katana triage laptop.E01

# Machine-parseable (pipe)
katana triage laptop.E01 | grep "CRITICAL"

# Explicit JSON output for tooling
katana triage laptop.E01 --format jsonl
```

### 0.5 Progress Bar Degradation

```
TTY mode:
[=================>          ] 67% Parsing USN records...

Non-TTY mode:
[INFO] Parsing USN records: 25% complete
[INFO] Parsing USN records: 50% complete
[INFO] Parsing USN records: 75% complete
[INFO] Parsing USN records: 100% complete

TERM=dumb mode:
Parsing USN records: 25% complete
Parsing USN records: 50% complete
Parsing USN records: 75% complete
Parsing USN records: 100% complete
```

### 0.6 CLI Error Output

Errors always go to stderr with clear, parseable formatting. Every error follows the three-part pattern: what happened, why, and what to do.

```
ERROR: Failed to mount evidence image.
Reason: EWF file signature invalid at offset 0x0.
Action: Verify the file is a valid E01/EWF image. Run 'katana verify laptop.E01' to check integrity.
```

## 3. Screen Reader Patterns

Security Ronin Katana has three distinct screen reader contexts: CLI terminal output, static HTML reports, and real-time enterprise web UI with WebSocket collaboration.

### 3.1 HTML Report Landmarks

The HTML report uses semantic landmarks for efficient screen reader navigation.

```html

  <header role="banner">
    <h1>Security Ronin Katana -- Triage Report</h1>
    <p>Case: <span>{{case_id}}</span> | Generated: <time>{{timestamp}}</time></p>
  </header>

  <main id="triage-results" role="main">
    <section aria-label="Evidence Summary Statistics">
      <div id="stat-cards" role="group" aria-label="Key metrics">
        <!-- Stat cards with individual aria-labels -->
      </div>
    </section>

    <nav aria-label="Report sections">
      <div role="tablist" aria-label="Report views">
        <button role="tab" aria-selected="true" aria-controls="tab-story" id="btn-story">
          Story
        </button>

        </button>
```

### 3.6 Pipeline Progress Announcements

The triage pipeline has defined stages. Announcements are coalesced to avoid overwhelming screen reader users during the ~35-second processing window:


### 3.7 WebSocket Collaboration Announcements

When multiple analysts collaborate on a case, WebSocket messages must be announced without creating a wall of noise:

```javascript
// enterprise/static/js/collab-a11y.js

const COLLAB_COALESCE_MS = 10000; // Announce at most once per 10 seconds
var collabBuffer = [];
var collabTimer = null;

function onCollabMessage(msg) {
  collabBuffer.push(msg);
  if (!collabTimer) {
    collabTimer = setTimeout(flushCollabAnnouncements, COLLAB_COALESCE_MS);
  }
}

function flushCollabAnnouncements() {
  collabTimer = null;
  if (collabBuffer.length === 0) return;

  var collabLog = document.getElementById('collab-activity');

  if (collabBuffer.length === 1) {
    var msg = collabBuffer[0];
    var announcement = document.createElement('div');
    announcement.textContent = formatCollabMessage(msg);
    collabLog.appendChild(announcement);
  } else {
    var summary = document.createElement('div');
    var analysts = [];
    collabBuffer.forEach(function(m) {
      if (analysts.indexOf(m.analyst) === -1) analysts.push(m.analyst);
    });
    summary.textContent =
      collabBuffer.length + ' collaboration updates from ' +
      analysts.length + ' analyst(s).';
    collabLog.appendChild(summary);
  }

  collabBuffer = [];

  // Prune old entries to prevent DOM growth
  while (collabLog.children.length > 20) {
    collabLog.removeChild(collabLog.firstChild);
  }
}

function formatCollabMessage(msg) {
  switch (msg.type) {
    case 'analyst_joined':
      return msg.analyst + ' joined the case.';
    case 'analyst_left':
      return msg.analyst + ' left the case.';
    case 'finding_added':
      return msg.analyst + ' added a ' + msg.severity + ' finding.';
    case 'note_added':
      return msg.analyst + ' added a note to question ' + msg.questionNumber + '.';
    case 'case_status_changed':
      return 'Case status changed to ' + msg.newStatus + ' by ' + msg.analyst + '.';
    default:
      return 'Case update from ' + msg.analyst + '.';
  }
}
```

### 4.1 Focus Strategy by Surface and State

```javascript
function onFormValidationFail(errors) {
  var errorSummary = document.getElementById('form-errors');
  var errorList = errorSummary.querySelector('ul');
  errorList.innerHTML = '';

  errors.forEach(function(err) {
    var li = document.createElement('li');
    var link = document.createElement('a');
    link.href = '#' + err.fieldId;
    link.textContent = err.fieldLabel + ': ' + err.message;
    li.appendChild(link);
    errorList.appendChild(li);
  });

  // Show and focus error summary
  errorSummary.hidden = false;
  errorSummary.focus();

  // Mark individual fields
  errors.forEach(function(err) {
    var field = document.getElementById(err.fieldId);
    field.setAttribute('aria-invalid', 'true');

    var errorEl = document.getElementById(err.fieldId + '-error');
    if (!errorEl) {
      errorEl = document.createElement('p');
      errorEl.id = err.fieldId + '-error';
      errorEl.className = 'form-error';
      errorEl.setAttribute('role', 'alert');
      field.parentNode.appendChild(errorEl);
    }
    errorEl.textContent = err.message;

    var describedBy = field.getAttribute('aria-describedby') || '';
    if (describedBy.indexOf(errorEl.id) === -1) {
      field.setAttribute('aria-describedby', (describedBy + ' ' + errorEl.id).trim());
    }
  });
}
```

### 7.3 Focus Trap for Modals (Enterprise Web)

```javascript
// enterprise/static/js/modal.js

function trapFocus(modalElement) {
  var focusableSelectors = [
    'a[href]', 'button:not([disabled])', 'input:not([disabled])',
    'select:not([disabled])', 'textarea:not([disabled])',
    '[tabindex]:not([tabindex="-1"])'
  ].join(', ');

  var focusable = modalElement.querySelectorAll(focusableSelectors);
  var firstFocusable = focusable[0];
  var lastFocusable = focusable[focusable.length - 1];

  // Store trigger element to restore focus on close
  modalElement._triggerElement = document.activeElement;

  firstFocusable.focus();

  modalElement.addEventListener('keydown', function handler(e) {
    if (e.key === 'Escape') {
      closeModal(modalElement);
      return;
    }

    if (e.key !== 'Tab') return;

    if (e.shiftKey) {
      if (document.activeElement === firstFocusable) {
        e.preventDefault();
        lastFocusable.focus();
      }
    } else {
      if (document.activeElement === lastFocusable) {
        e.preventDefault();
        firstFocusable.focus();
      }
    }
  });
}

function closeModal(modalElement) {
  modalElement.hidden = true;
  modalElement.setAttribute('aria-hidden', 'true');

  if (modalElement._triggerElement) {
    modalElement._triggerElement.focus();
  }
}
```

### 9.3 CLI Severity (NO_COLOR Mode)

When color is unavailable, severity is communicated through text labels and ASCII symbols:

```
[!!] CRITICAL: Endpoint protection disabled (3 entries)
[!]  HIGH:     Suspicious PowerShell execution (7 entries)
[~]  MEDIUM:   USB device connected during incident window (2 entries)
[-]  LOW:      Standard software installation (12 entries)
[.]  INFO:     Normal user file operations (847 entries)
[G]  GHOST:    Recovered deleted antivirus log entries (14 entries)
```

### 9.4 Color-Blind Simulation Verification

The design system must be verified under the three most common color vision deficiencies:

| Deficiency | Prevalence | Risk | Mitigation |
|------------|-----------|------|------------|
| Protanopia (no red) | ~1% male | Critical/High may look similar | Different icons (ShieldAlert vs AlertTriangle) + text labels + solid vs solid fill |
| Deuteranopia (no green) | ~6% male | Success/warning may blur | Success uses checkmark icon + "COMPLETE" text |
| Tritanopia (no blue) | ~0.01% | Low severity may lose contrast | Low uses Info icon + text + outline border |

All severity indicators remain distinguishable via icon shape + text label + border pattern (solid/outline/dashed) even with complete color blindness (achromatopsia).

## 10. Testing Protocol

### 10.1 Automated Testing

**CLI accessibility tests (Rust integration tests):**

```rust
// tests/cli_accessibility.rs

#[test]
fn test_no_color_strips_ansi() {
    let output = Command::new("katana")
        .arg("triage")
        .arg("tests/fixtures/small.E01")
        .env("NO_COLOR", "1")
        .output()
        .expect("Failed to run katana");

    let stdout = String::from_utf8_lossy(&output.stdout);
    assert!(!stdout.contains('\x1b'), "Output contains ANSI escapes with NO_COLOR set");
    assert!(stdout.contains("[CRITICAL]") || stdout.contains("[HIGH]"),
        "Text severity labels missing in NO_COLOR mode");
}

#[test]
fn test_pipe_strips_ansi() {
    let output = Command::new("katana")
        .arg("triage")
        .arg("tests/fixtures/small.E01")
        .stdout(Stdio::piped())
        .output()
        .expect("Failed to run katana");

    let stdout = String::from_utf8_lossy(&output.stdout);
    assert!(!stdout.contains('\x1b'), "Output contains ANSI escapes when piped");
}

#[test]
fn test_term_dumb_strips_ansi() {
    let output = Command::new("katana")
        .arg("triage")
        .arg("tests/fixtures/small.E01")
        .env("TERM", "dumb")
        .output()
        .expect("Failed to run katana");

    let stdout = String::from_utf8_lossy(&output.stdout);
    assert!(!stdout.contains('\x1b'), "Output contains ANSI escapes with TERM=dumb");
}

#[test]
fn test_severity_labels_always_present() {
    let output = Command::new("katana")
        .arg("triage")
        .arg("tests/fixtures/small.E01")
        .env_remove("NO_COLOR")
        .output()
        .expect("Failed to run katana");

    let stdout = String::from_utf8_lossy(&output.stdout);
    let has_severity = stdout.contains("CRITICAL") ||
                       stdout.contains("HIGH") ||
                       stdout.contains("MEDIUM") ||
                       stdout.contains("LOW") ||
                       stdout.contains("INFO");
    assert!(has_severity, "Severity text labels missing from output");
}
```
